# Documentation map

- `00-source-boundaries-and-decisions.md`: source evidence versus explicit engineering choices.
- `product/`: product requirements, scope, roles, workflow, acceptance criteria.
- `architecture/`: runtime components, data flow, storage, audit, queues and decisions.
- `data/`: data dictionary and relational constraints.
- `api/` and `../contracts/`: REST surface, stable errors and machine-readable draft contracts.
- `ai/`: trust limits, prompts/schema and evaluation plan.
- `security/`: tenant isolation, threat model and release checks.
- `frontend/` and `backend/`: page/component and service boundaries.
- `operations/`: local setup, env, deployment, backups and observability.
- `testing/`: strategy and scenarios.
- `implementation/`: build order, conventions and definition of done.
- `file-specs/`: per-file responsibilities/checklist.
- `markdown-inventory.md`: full Markdown navigation.

All requirements are proposed design unless explicitly attributed to the source deck. Market figures and sample measurements in the deck are not validated product outcomes.
